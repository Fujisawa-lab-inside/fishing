# YODA 河口堰マルチモーダル観測収集 v1

## 目的

河口堰カメラだけで A1〜A8 の開閉を推定せず、後日、画像と同時刻の水文条件を組み合わせて評価できる教師候補データを YODA ローカルへ蓄積する。

## 10分ごとの保存内容

- 遠賀川河口堰の公式カメラ JPEG
- 河口堰の公式流入量、放流量、上流水位、下流水位
- 河口堰の公式12時間流入・放流履歴
- 気象庁アメダス八幡の10分・1時間・3時間・24時間降水量
- 気象庁・博多の年潮位表（天文潮位の参照値）
- 各原本の URL、取得時刻、バイト数、SHA-256、解析結果

八幡雨量は流域平均ではない。博多潮位は遠賀川河口の実測潮位ではない。河口堰の点観測から門別開度や魚道流量を断定しない。

## 実行境界

収集器は1回だけ取得する `--once` だけを持つ。10分間隔は YODA の cron と `flock` が担当し、同じ10分枠は上書きしない。取得源の一部が欠測しても、その時点で得られた原本を `PARTIAL_CAPTURE_NO_GATE_INFERENCE` として保持する。

この段階では、門別状態推論、教師ラベル生成、モデル学習、パラメータ fitting、水理計算、GUI反映、公開を行わない。

## 保存場所

YODA ローカル正本:

`/home/swarm/work/seabass_observations/gate-multimodal-v1`

NAS は `swarm` の書込み先が用意された後に、別の同期処理として追加する。収集処理を NAS の可用性に依存させない。

## 公式YouTubeライブの短時間補助取得

遠賀川河川事務所の公式YouTubeライブでは、多数の河川カメラが約15〜20秒ずつ切り替わり、`遠賀川水系遠賀川 右岸 2k000` の画角で河口堰全8門を確認できる。動画は10分静止画より回転灯の明滅を取りこぼしにくいため、門別状態の**正の手掛かり候補**として追加する。

初回は `tools/stage20_youtube_barrage_live_capture_v1.py` で最大900秒、2 fps、最大720 pxの校正フレームだけをYODAへ保存する。24時間動画、期限付きの署名済みmedia URLは保存しない。校正後は2k000画角の15〜20秒だけを残す方式へ移行する。

同一門の西側・東側にあるオレンジ回転灯の時間変化を確認できた場合だけ、その門が作動中である正の手掛かりにする。映らない、消灯している、雨滴・白飛びで読めない場合は `UNKNOWN` であり、閉門とは扱わない。対象区間抽出、灯位置校正、門番号対応の確認が終わるまで、推定器や教師ラベルへ自動投入しない。

長時間の校正観測では常時動画を保存しない。既存10分観測の公式総放流量が `1.0 m3/s` 以上、または前回から `0.5 m3/s` 以上増加した時だけ10分動画を取得する。高放流が続く場合も取得間隔は1時間以上とし、最大16回で停止する。判定と取得はYODA内で完結し、GPTが10分ごとに画像を読む必要はない。取得失敗時は `FAILED_NO_RETRY` で停止し、原因を確認せず再投入しない。
