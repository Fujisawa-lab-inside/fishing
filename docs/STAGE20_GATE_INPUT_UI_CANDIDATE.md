# Stage 20 河口堰開門入力UI候補

## 位置づけ

この文書は、`stage20-hybrid-gui.html` に置く河口堰1〜8番水門の入力UI契約を固定します。対象はGUI表示、操作説明、静的検証だけです。

`synthetic`と保存済みreplayでは、水門入力は表示専用で流速・水深・流向・時刻系列を変更しません。例外は `local_r1c_experiment`で、利用者が計算ボタンを押した時点の8門入力だけを固定し、最大300秒のローカルR1C solver結果へ反映します。河川流量・潮位の表示系列はそのローカル物理境界へ未接続です。モード境界は `config/stage20_runtime_capabilities_v2.json` に固定します。

魚道は主水門1〜8とは別系統です。GUIでは「魚道：常時有効・操作不可」を固定表示します。`synthetic`では表示専用、保存済みR1Cとlocal実験では未較正の集約C2.1 storage表現であり、較正済み魚道流量や現地操作権限を意味しません。

## 水門位置表示の意味論

水門番号1〜8の地図表示は、`docs/results/stage20-barrage-pink-structure-alignment-candidate-v2/gate-reference-anchor-authority-v2.geojson` のA1〜A8を使用します。これらはユーザー提供EPSG:4326座標を保持する**番号参照アンカー**であり、厳密な幾何中心ではありません。旧 `gate_center` の「確定中心」という意味論は撤回済みです。

- A1〜A8は西から東への番号対応を示す点です。
- A1〜A8から物理端面を導出しません。
- 46.5mは8門共通のモデル開口幅契約です。地理的な実位置線、写真上の端面間距離、またはアンカー中心線として描画しません。
- 写真可視端点は8門・16/16点が承認済みです。ただし、写真座標のレビューauthorityであり、物理メッシュ採用ではありません。
- 地図には番号アンカー点、開・閉・未入力の状態バッジ、写真可視端点のレビュー用破線overlayを表示します。46.5mの地理的線分は表示しません。

## 2つのモード

### 自動推定

- 現在選択中の時刻にある全体開門率を0〜1へ収め、`round(全体開門率 × 8)` で整数の開門段階0〜8を推定します。
- 推定段階を固定順序 `5 → 4 → 6 → 3 → 7 → 2 → 8 → 1` で、1〜8番水門それぞれの0%（閉）または100%（開）へ変換します。
- 各門を一律の中間開度、たとえば全門50%として扱いません。
- 時刻を変更した場合は自動推定を更新します。

### 現地目視入力

- 1〜8番を個別に開（100%）または閉（0%）で入力します。
- 現地入力が有効な間は、自動推定を表示上で明示的に上書きします。
- 入力元と観測時刻を現地入力に付随するメタデータとして表示します。
- 現在時刻の自動推定と異なる水門番号、および差の門数を表示します。
- 「自動推定へ戻す」で現地入力による上書きを終了し、現在時刻の自動推定を再び有効にします。

入力値とメタデータは、この画面を開いている間だけの表示メモです。必要な場合は固定schemaのcanonical JSONとして端末へDLし、同じschemaのローカルJSONを再読込できます。読込内容はfail-closedで検証し、欠落・追加gate key、boolean、範囲外値、timezoneなし時刻を拒否します。再読み込み時の自動保存、物理計算、応答pack更新、外部送信、公開画面反映は行いません。

## 固定開門順序と9状態

各行は、水門番号1〜8の順です。値は0%が閉、100%が開を表します。

| 段階 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 開いている門 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | なし |
| 1 | 0 | 0 | 0 | 0 | 100 | 0 | 0 | 0 | 5 |
| 2 | 0 | 0 | 0 | 100 | 100 | 0 | 0 | 0 | 5, 4 |
| 3 | 0 | 0 | 0 | 100 | 100 | 100 | 0 | 0 | 5, 4, 6 |
| 4 | 0 | 0 | 100 | 100 | 100 | 100 | 0 | 0 | 5, 4, 6, 3 |
| 5 | 0 | 0 | 100 | 100 | 100 | 100 | 100 | 0 | 5, 4, 6, 3, 7 |
| 6 | 0 | 100 | 100 | 100 | 100 | 100 | 100 | 0 | 5, 4, 6, 3, 7, 2 |
| 7 | 0 | 100 | 100 | 100 | 100 | 100 | 100 | 100 | 5, 4, 6, 3, 7, 2, 8 |
| 8 | 100 | 100 | 100 | 100 | 100 | 100 | 100 | 100 | 5, 4, 6, 3, 7, 2, 8, 1 |

`gatePatternForStage(stage)` は上表の数値配列を返します。`classifyGatePattern(levels)` は完全一致する場合に段階0〜8を返し、一致しない場合は `null` を返します。

## 現地入力の判定

- 現地入力が上表のいずれかと完全一致する場合は「標準段階0〜8」と表示します。
- それ以外の組合せは入力を拒否せず、「標準順序外」と警告します。
- 「標準順序外」は固定順序との不一致を表す表示上の警告であり、現地観測の誤りを意味しません。
- 自動との差は、各門を0%か100%として比較します。開閉が異なる門だけを差として数えます。

## 表示契約

GUIには少なくとも次を同時に確認できる領域を置きます。

- モード: 「自動推定」「現地目視入力」
- 自動推定値: 段階0〜8と、固定順序から得た1〜8番の開閉
- 有効値: 現在地図に重ねている1〜8番の開閉
- 現地入力メタデータ: 入力元、観測時刻
- 比較: 自動推定との差
- 分類: 標準段階、または「標準順序外」
- 操作: 「自動推定へ戻す」
- ローカル入出力: 観測JSONの検証読込、現在の現地入力のcanonical JSONダウンロード
- 非接続表示: 「流れの図には未反映」
- 魚道状態: 「魚道：常時有効・操作不可」
- 全閉時の魚道表示: 主水門が8門とも閉でも、魚道による上流・下流接続を固定表示する
- 魚道の非接続表示: 「物理solver・応答pack未接続／流れ図未反映」
- 水門番号位置: `gate-reference-anchor-authority-v2.geojson` のA1〜A8を番号参照アンカーとして投影する
- 水門位置の注意: A1〜A8は厳密な幾何中心ではなく、物理端面の導出には使用しない
- 幅の注意: 46.5mはモデル開口幅契約であり、地理的な実位置線として描画しない
- 端面状況: 「写真可視端点 16/16 承認」と「物理メッシュ 採用未承認」を別項目で表示する
- 魚道位置: 固定された `onga_geometry.geojson` の魚道提供緯度経度をそのまま表示へ投影する

A1〜A8と魚道位置は写真抽出やメッシュセル中心へスナップしません。ただし、A1〜A8を物理水門の中心または端面として扱うことも禁止します。写真可視端点は `stage20_barrage_gate_photo_visible_faces_authority_v1.geojson` を直接投影し、レビュー表示にだけ使います。岸線補正で移動できるのは周囲の水面・陸地境界だけです。魚道の表示中心を上流・下流メッシュセルの平均で置き換えることも禁止します。

魚道状態は表示専用の固定ステータスで、ボタン、チェックボックス、開閉値、プリセットを持ちません。自動推定、標準順序に一致する現地入力、標準順序外の現地入力のいずれへ切り替えても変更・非表示にしません。

## 非接続境界

この候補で変更してよいのは、`stage20-hybrid-gui.html`、`stage20-hybrid-gui.css`、`onga_stage20_gui.mjs`、`onga_stage20_gui_data.mjs` の固定座標読込、GUI文書、静的validatorです。

次は変更禁止です。

- `onga_stage20_gui_data.mjs` から合成Workerへ渡すメッセージ（魚道の固定表示座標はWorkerへ渡さない）
- `onga_stage20_hybrid_worker.mjs` の入力契約
- Stage 20物理solver、応答pack、メッシュ、事前計算結果
- 公開シミュレーター、公開配信、`main` 反映

## 静的検証

```sh
python3 tools/validate_stage20_runtime_baseline_v2.py --workspace-candidate
node tools/validate_stage20_runtime_capabilities_v2.mjs
python3 tools/validate_stage20_gui_integration_status_manifest_v1.py
node tools/validate_stage20_gui_integration_runtime_v1.mjs
```

既存v1 validatorとvalidation結果は旧display-only契約の履歴として変更しません。local solverを含む現行GUIはRuntime Capability Contract v2を正本候補として検証し、v1を現行合否へ使用しません。
